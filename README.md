# Начальная настройка программы

Инструкция предназначена для специалистов заказчика, начинающих использовать доработку в базе с действующим учётом. Названия приведены по ТЗ: точные пути к командам необходимо сверить с выполненной реализацией.

## 1. Подготовка базы

**Администратор:**

1. Согласуйте с бухгалтером дату начала использования новых механизмов, желательно с начала месяца.
2. Сделайте резервную копию базы. Проверьте установку доработки на копии, затем установите её в рабочую базу по инструкции разработчика.
3. Проверьте наличие подсистемы «Обслуживание клиентов», новых документов, отчётов и профилей доступа.

Используйте существующих контрагентов, сотрудников и номенклатуру, не создавая дубликатов. В тестовой базе отключите отправку уведомлений в рабочую Telegram-группу.

## 2. Права пользователей

**Администратор:** создайте группы доступа на основе поставляемых профилей и включите в них пользователей.

| Профиль | Назначение |
| --- | --- |
| Специалист | Документы обслуживания, выполненные работы, присоединённые файлы, отчёт по выработке |
| Менеджер | Регистрация и планирование заявок, назначение специалиста |
| БухгалтерИТФирмы | Реализации, массовое создание и печать актов, анализ выставленных актов |
| КадровикРасчетчик | Условия оплаты, зарплата, премии, выплаты, отпуска; отчёты по выработке, зарплате и отпускам |

Сохраните права, необходимые для исходной конфигурации. При совмещении обязанностей назначьте несколько групп. Проверьте доступ под учётной записью каждого типа пользователя, включая доступ бухгалтера к реализациям.

## 3. Номенклатура и константы

**Бухгалтер совместно с администратором:** подберите или создайте две позиции номенклатуры с видом «Услуга», заполните необходимые настройки учёта и НДС. Для работ специалиста укажите единицу измерения, соответствующую часам.

Заполните константы:

| Константа | Что указать |
| --- | --- |
| НоменклатураАбонентскаяПлата | Услугу для ежемесячной абонентской платы |
| НоменклатураРаботыСпециалиста | Услугу для оплачиваемых часов специалиста |
| Токен управления телеграм-ботом* | Токен используемого бота |
| Идентификатор группы для оповещения* | Идентификатор группы специалистов |

\* Технические названия Telegram-констант необходимо уточнить по реализации.

**Обе номенклатурные константы обязательны:** без них автозаполнение реализации прекращается. Последующую замену номенклатуры работ согласовывайте с бухгалтером: она используется при анализе выставленных актов.

## 4. Договоры

**Ответственный за договоры:** для каждого клиента создайте или настройте договор абонентского обслуживания. Заполните:

- новый вид договора — абонентское обслуживание;
- даты начала и окончания действия;
- сумму ежемесячной абонентской платы;
- стоимость часа работы специалиста;
- остальные обязательные реквизиты исходной конфигурации.

Не изменяйте вид действующего договора без проверки влияния на ранее введённые документы. При проведении обслуживания проверяется попадание **даты документа** в срок договора.

## 5. Условия оплаты сотрудников

**Кадровик-расчётчик:** заполните регистр «УсловияОплатыСотрудников» с месяца начала использования доработки:

- для всех сотрудников — оклад;
- для специалистов — процент от выполненных работ;
- для сотрудников без процентного вознаграждения — нулевой процент.

Регистр имеет периодичность «Месяц». При вводе прошлых документов условия должны действовать на их даты.

**Отсутствие установленного процента у специалиста блокирует проведение обслуживания; нулевой процент допускается.**

Необходимость заполнения календаря, графиков работы и видов расчёта уточните по реализации. В константе хранится значение НДФЛ - 13%

## 6. Telegram и присоединённые файлы

**Администратор:**

1. Подготовьте бота, добавьте его в группу специалистов и обеспечьте возможность отправки сообщений. Заполните константы из раздела 3.
2. Проверьте доступ к Telegram из среды выполнения отправки.
3. Включите регламентное задание отправки уведомлений, настройте расписание и разрешите выполнение фоновых заданий.
4. На тестовой группе проверьте уведомления при создании заявки и изменении даты, времени или специалиста.
5. Перед включением рабочей группы проверьте очередь на наличие тестовых сообщений.
6. Проверьте настройки хранения файлов: специалист должен иметь возможность прикрепить и повторно открыть скан листа учёта времени. 

Сообщения накапливаются в справочнике «Уведомления телеграм-боту» и удаляются после успешной отправки. При сбое проверьте очередь и результат выполнения задания.

## 7. Начальные данные и отпуска

**Бухгалтер и кадровик-расчётчик совместно с разработчиком:** до запуска согласуйте перенос:

- работ за первый расчётный месяц, если переход выполняется внутри месяца;
- задолженности перед каждым сотрудником на дату перехода;
- начислений за предыдущие 12 месяцев и рабочих дней для расчёта отпускных;
- истории условий оплаты, если будут учитываться прошлые периоды;
- плановых и фактических отпусков за год запуска.

Старые документы не гарантируют наличия данных в новых регистрах. Способ переноса в ТЗ не указан: используйте согласованный с разработчиком порядок, без произвольного изменения регистров и массового перепроведения документов.

Создайте «ГрафикОтпусков» на нужный год, заполните сотрудников и периоды. Проверьте подсветку отпусков свыше 28 дней и пересечения на диаграмме анализа. Способ регистрации фактического отпуска для расчёта зарплаты уточните отдельно.

## 8. Проверка перед запуском

На копии базы проверьте полный цикл:

1. Запишите и проведите обслуживание по действующему договору. Проверьте уведомление, вложение и отражение работ клиента и вознаграждения специалиста.
2. Заполните реализацию: должны появиться ненулевая абонентская плата и работы за месяц даты документа. **Автозаполнение очищает прежние строки.**
3. Запустите массовое создание актов за нужный месяц повторно: дубли реализаций создаваться не должны. Проверьте также распознавание реализаций, введённых до перехода.
4. Напечатайте акт, проверьте реквизиты, суммы и подписи. При необходимости отредактируйте макет предусмотренной командой.
5. Рассчитайте зарплату и премию, проверьте НДФЛ, заполните выплату и сверьте задолженность.
6. Проверьте показатели отчётов и доступ к ним по профилям.

После успешной проверки перенесите настройки в рабочую базу и сообщите пользователям дату начала работы.
